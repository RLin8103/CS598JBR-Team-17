Targeted libpsbt repair experiment, using the existing agent-generated implementation. Prefer small <edit> blocks. Extra regression feedback is separate from protected benchmark tests.

Defects verified against the supplied C:
- psbt_read increments kvs after each record in addition to map boundaries. C increments only at input/output map boundaries, so multiple records in a map must share the map index and must not advance scope. A 2-input/2-output fixture with two records per map currently retains only 2/2/2 records by scope instead of 2/4/4.
- C tx_counter forwards transaction callbacks before the unsigned-transaction record callback. Rust tx_io_counts discards those events. Preserve TxIn,TxIn,TxOut,TxOut,Tx ordering, then the global record, for a two-input/two-output transaction. C does not initialize the outer psbt_elem.index for TxElem events: do not invent a C expectation for it. Record indices are defined.
- psbt_decode ignores src_size and psbt_encode_raw ignores psbt_len. Process exactly the requested byte prefix. Reject requests exceeding the backing input; avoid UTF-8 slicing panics. src_size is a byte count.
- Enforce both actual destination slice length and declared capacity consistently in all encoding/decoding paths. Hex currently panics on short actual buffers; Base64/Base62 ignore small declared limits. Error variants should agree with defined C paths (ReadError for decode bounds, OobWrite for hex encode, WriteError for Base64/Base62 encode failure). Do not write past the effective limit.
- Base62 uses 6-bit indices but a 62-symbol table. C has a 63-byte array including a NUL at index 62; index 63 is out of bounds. Rust panics for 62/63. Preserve the defined 0..61 mapping. Checked failure (None/WriteError) for unrepresentable indices is a safety extension pending instructor clarification; document it rather than silently inventing a new alphabet/radix.
- Unknown global record types must label UNKNOWN_GLOBAL_TYPE, as C psbt_type_tostr does. The enum-only psbt_global_type_tostr cannot represent invalid discriminants; do not create them.
- PSBT_ERRMSG and psbt_geterr are fixed-string bodies already present in the skeleton. Dynamic context is a skeleton limitation; do not change their public types. The separate error-context test is a requested improvement, not an official compatibility test.
- compactsize_write has no Result return in the interface. Short destinations currently panic and may be partly modified; ensure checked behavior consistent with the available signature, and document any chosen failure policy. C has no capacity parameter and is not an oracle for short buffers. C multi-byte compactsize_write also overwrites its marker (253 in an aa-filled buffer yields fd00aa); Rust implements standard fd fd 00. This is a C/spec ambiguity, not an excuse to corrupt a standard encoding silently.
- cli::main is private in a library module, exactly as the skeleton requires, with no CLI binary target. Document the integration limitation; do not modify Cargo.toml or lib.rs to manufacture an executable.

Known benchmark concern: read_test_vector declares a fresh local step on every callback; C uses a persistent counter in user_data, incremented for all events. Preserve the supplied test, report its failure, and do not spend repeated turns on that unchanged issue. Do not special-case data, skip it, alter public interfaces, or treat it as passing. Use the additional independent regressions to guide real repairs. No official unsafe analyzer is currently configured; record it as unavailable.
